The prediction that was wrong

docs/20 pre-registered that in-domain performance was expected to get worse with augmentation off, on the strength of Pre-Aug 12.870% vs G4 11.212%. That did not happen. Arm B is better in-domain on every axis — pooled EER (−6.196 pp s42, −2.765 pp s43), minDCF (0.9686 → 0.6991), A19, A20, and dev EER (−9.128 pp s42, −6.686 pp s43).

So this is not the trade-off that was hypothesised. It is not “augmentation buys benchmark numbers at the cost of the real world”. It is augmentation costs on both and buys nothing. The earlier docs/08 comparison was confounded — Pre-Aug and Post-Aug were separate runs whose seed, epoch count and recipe were never controlled, and docs/20 said so at the time. The paired, flag-flipped run resolves it the other way.

Why that is plausible

ASVspoof 5 was already captured over real telephone networks, so clean in this corpus is the call condition. Applying a synthetic codec/telephony chain on top double-transcodes the input and pushes it off-distribution relative to both eval and ITW — the augmenter teaches invariance to distortions the deployment signal does not contain.

A second, consistent signal: out-of-domain seed spread collapses when augmentation is off — 6.237 pp (arm A) → 1.942 pp (arm B) on full_call. Augmentation was not only shifting the mean, it was destabilising training.

Read the spread, not any single row. w_cm moves 33× and w_asv 49× across a plausible L2 range, so there is no identifiable “best” value — only a band. The default l2=1.0 row (0.6054 / 1.1902) looks like it indicts the deployed preset (1.5 / 2.0) as over-weighting by ~2.5×, but that is an artefact of an arbitrary default, not evidence.
Conclusion: leave w_cm=1.5 / w_asv=2.0 alone. The preset sits inside the band at roughly L2 ≈ 0.28–0.55, toward the conservative end and well below the aggressive l2=0.1 fit (2.4469 / 6.3502). Changing it on a point estimate from 170 samples would be fitting to noise.

Trap found: load_anchor() is not optional. Skip it and asv_mismatch is constant, so w_asv silently fits to 0.0000 — which reads as “ASV doesn't matter” when it is really a missing-data artefact. Also do not export VR_FUSION_W_CM / VR_FUSION_W_ASV to “fix” the fusion: an explicit env var overrides the backend's real-backend preset and re-introduces the false-alarm behaviour that preset exists to remove.

Shipping recommendation

Ship arm B (--no-codec-augment), not the G4 / augmented line.
Arm B wins on the deployment distribution (ITW full_call: 33.979 / 35.921 vs 44.541 / 38.304), wins on the in-domain benchmark, and has 3× lower seed variance. There is no axis on which the augmented models win, so there is no trade-off to adjudicate.

Two consequences that must travel with it

  • The docs/10 headline metric needs revisiting. It is written on ASVspoof 5 pooled EER, which here ranks the models correctly by luck — arm B happens to win both. The converse does not hold: docs/18 measured an inversion across four models. Select on the deployment distribution.
  • Calibration: DONE. Both arm B checkpoints carry a Platt block and pass the G2 criterion (calibrated eval CLLR 0.4271 / 0.4112 — the best in the repo), and arm B s42 passes the live backend load proof. Remaining: re-fit the fusion weights w_cm / w_asv against this head; they are still fitted to the old LLR distribution.
  • Do not retrain to chase a better number. Ground rule 5 applies — publish as measured.
